# 039 本地产品化审计与界面统一

## 背景

当前跨境物流版本仍暴露旧电商项目的品牌、分类器页面和示例数据；聊天页与后台使用两套视觉语言，模型思考链配置还会让流式问答长时间拿不到正文，最终在前端统一显示“回复失败”。

## 目标

1. 聊天工作台与全部后台入口统一为“航迹云”物流品牌和同一套蓝绿视觉系统。
2. 后台首页只展示当前物流项目真正可解释的数据：运单态势、知识库、Agent 评测、RAG 评测、失败复盘、观测和主题分布。
3. 旧电商分类器验收页面不再作为产品入口，历史 API 和训练脚本保留用于代码研究。
4. 修复本地聊天持续失败：关闭不兼容的思考链、设置上游超时、向前端透传可读错误。
5. 清理主链路 Prompt 和演示数据中的猫用品、电商平台等语义，替换为跨境物流语境。

## 非目标

- 不删除历史训练脚本和旧评测数据，避免破坏已有实验复现能力。
- 本轮不部署服务器；本地验收并由用户确认后再发布。

## 验收标准

- `/`、`/admin` 以及所有后台导航页采用一致的航迹云配色、圆角、卡片和导航。
- 用户可见页面中不再出现“喵喵优选”、猫用品或旧电商分类器入口。
- `/api/admin/overview` 首卡为物流运营态势，且不再返回旧分类器验收卡。
- 本地 `/api/chat` 对物流知识问题返回正文、引用、`done` 与 `[DONE]`。
- 上游失败时前端展示后端返回的具体错误，而不是无条件显示“回复失败”。
- 相关静态页、后台 API、Prompt 与物流回归测试通过。

## 兼容性修复记录

- DeepSeek 普通对话继续流式输出；意图识别、查询改写和证据自检等结构化调用改为非流式，规避该模型流式工具参数解析失败。
- 该切换只影响内部结构化步骤，不影响聊天页逐字展示主回答。
