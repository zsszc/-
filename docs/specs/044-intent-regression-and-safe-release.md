# Spec 044：意图识别稳定性、全量回归与安全提交

## 背景

DeepSeek 结构化工具调用偶发连续解析失败，现有降级仅识别“清关/报关”，其他物流问题可能误路由。300 条物流 Agent 评测集已有脚本，但当前在线评测只在全部结束后落盘，中断会丢失进度。工作区积累了多个已验收功能改动以及已追踪的运行报告，需要在提交前隔离密钥与产物。

## 范围

1. 意图识别先沿用当前 function calling；解析失败时仅对意图槽位尝试一次 DeepSeek 官方支持的 JSON Output，以 Pydantic 九类枚举和置信度范围做严格校验。若 JSON 缺失、无效或上游失败，才走保守词规则／“其他”出口。不得将模型原始响应和密钥写入日志。
2. 扩充保守词规则覆盖明确的运单、清关、费用、异常、理赔、禁限寄、人工诉求；冲突或不明确时回到“其他”，不把库外题强行归业务类。
3. 在线 Agent 评测默认跑完整 300 条，按小批量写入 Git 忽略的本地报告，可按 ID 断点续跑并只补失败请求。报告区分服务请求失败、行为未通过与未完成，避免把缺项算成成功。
4. 跑全量 pytest、物流检索和 Agent 在线评测；必要时对发现的真实失败做有限范围修复并重测。给出总通过率、各类通过率、服务失败数和代表性失败原因，不用离线指标冒充在线成绩。
5. Git 仅纳入源码、测试、spec、非敏感评测题集；排除 `.env`、原始在线回答、日志、成本/趋势运行产物。检查暂存差异和密钥特征后提交并推送 GitHub。服务器部署不在本轮范围。
6. 真实评测发现裸 Uvicorn 环境下业务 MCP 未启动；本机 HTTP 代理也可能拦截回环 MCP。补齐两台 MCP 服务，并只对回环 MCP URL 禁用代理；远程 MCP 保留代理环境。前 80 条诊断样本保存在 v2 本地报告，完整基准另用 v3 报告从零运行，不混用环境。

## 验收

- 结构化工具调用失败后，JSON 兜底成功时仍能输出受枚举约束的正确意图；JSON 也失败时明确物流题有保守路由，库外题保持“其他”。
- 评测可中断续跑，最终报告覆盖 300 个唯一 ID；如上游额度/服务阻碍，明确已完成数与剩余数，不伪报全量。
- 全量测试完成，关键聊天/工具/拒答在线样本可复现。
- Git 提交不包含密钥、`.env`、模型原始回答或运行报告；远端推送成功。本地与服务器版本差异明确记录。

## 实现记录

- `app/core/intent.py` 保留函数调用主路径；两次结构化解析仍失败时，尝试 JSON Output 并用九类枚举与 0–1 置信度校验；再次失败才按单一明确关键词保守降级。
- `scripts/eval_logistics_agent.py` 支持每 10 条原子 checkpoint、断点续跑及仅重试请求错误；前 80 条无 MCP 的诊断样本保留在本地 v2 报告，不纳入下面 v3 成绩。Agent 评测页会显示完成进度，避免将未跑完的报告标成全量成绩。
- 本地启动物流和售后 MCP 服务后，v3 在 2026-09-20 完整跑完 300/300；接口请求失败 0，规则通过 163/300（54.33%）。分类：政策流程 55/100，跨文档 43/70，工具操作 24/60，库外拒答 31/50，边界澄清 10/20。报告位于 Git 忽略的 `data/evals/logistics_agent_eval_report_live_v3.json`，原始模型回答不提交。
- 失败归因：政策流程 45 条及跨文档 17 条缺规则所需证据；跨文档另 10 条未做缺运单号澄清；工具 36 条未命中预期工具；库外拒答 7 条先查 FAQ 后拒答、12 条不满足当前拒答文案/动作规则；边界澄清 10 条未命中当前澄清信号。规则偏保守：部分合理的先查库后拒答、缺参数先追问也会判失败，不能把 54.33% 解读为事实准确率。
- 最终全量 pytest 为 571 通过；本地重启服务后，清关知识问答、`query_shipment` 运单工具、库外航班题拒答三条烟测均 HTTP 200，评测页读取完成状态为 `ok`。一次沙箱内测试因本机网络权限受限而报连接错误；随后在允许连接本机 MySQL/Milvus 的环境中完整重跑通过。
- `.env`、原始在线报告、检索在线报告和 ch09 成本/趋势产物均排除 Git；六个此前已追踪的 ch09 运行报告从索引移除，本地文件保留。服务器部署不在本轮范围，服务器仍为旧版。
