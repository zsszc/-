# Spec 043：物流检索趋势与启动验收

## 背景

当前 Milvus 容器健康，但应用启动预热仍查询旧电商“退货运费”，会错误提示未就绪。观测页“重跑评估流水线”调用旧 `ch04` 电商题集，不应将其结果当作物流项目质量趋势。

## 范围与契约

1. 预热改用当前物流知识库中的固定问题，仍只做 BM25 只读检索，失败不阻断应用启动。
2. `make eval-flywheel` 与后台同名按钮改为运行物流检索趋势：复用 `data/evals/logistics_retrieval_eval.jsonl` 的 30 条标注样本与 `hybrid_rerank` 线上策略，只写 `eval_runs` 一轮。指标为 Recall@5、MRR@5、NDCG@5；样本查询出现异常时整轮失败，不写误导性的零分。
3. 趋势 API 只展示带物流数据集标记的轮次，旧电商轮次保留在库中但不混算。页面明确展示评测集、样本量、三个检索指标；忠实度和库外拒答不在本轮范围内。
4. 不写入 API 密钥、用户原文、模型原始响应到趋势产物。运行数据不提交 Git。
5. 真机冒烟若发现模型结构化意图解析失败，只对明确包含“清关/报关”的问题做保守物流意图降级；其他未知问题仍走原“其他”兜底，避免扩大误路由。
6. Langfuse 起停命令使用当前 `mewhelp-langfuse-compat` 项目名，避免误启动保留旧数据的栈。

## 验收

- 应用预热能命中物流知识，不再因旧查询产生假警告；聊天政策问答能返回可用答案。
- 上游意图解析失败时，明确清关问题仍进入清关检索；无关键词问题仍走“其他”。
- 趋势脚本在 30 条全成功时插入一轮；任一检索报错时不插入。
- 观测页能显示物流趋势，且不展示旧电商轮次。
- 单元测试、API 测试和本地浏览器验收通过。

## 实现记录

- Milvus 容器健康；预热问题从旧电商改为德国清关，应用启动日志确认“集合可检索”。
- 首次真实清关问答因 DeepSeek 结构化意图解析连续两次失败而落入“其他”兜底。仅对明确出现“清关/报关”的问题新增保守关键词降级；同题复测成功进入知识检索，回复德国个人件所需资料并带证据编号。
- `make eval-flywheel` 现运行 `scripts/eval_logistics_trend.py`，复用 30 条物流标注题的 `hybrid_rerank` 检索和现有纯函数指标。真实运行无检索错误，写入第 1 轮：Recall@5 `0.9611`、MRR@5 `0.9444`、NDCG@5 `0.9355`。
- API 只展示 `logistics_retrieval_v1` 标记的轮次；页面已实测显示 30 条样本和三个检索指标。旧电商轮次仍在库中但不混入展示，忠实度和拒答率明确标为未评估。
- 成本报告已基于新增匿名测试 Trace 重跑：3 次请求、14,185 Token；样本不足 5 次，不生成模型读图小注。
- Langfuse Makefile 起停目标已改为兼容栈项目名，避免误用旧数据卷。
- 相关测试 `46 passed`；最终重启时 Milvus 预热成功，浏览器复核观测页同时显示 3 次请求、14,185 Token 和第 1 轮物流检索趋势。本轮未部署服务器、未提交或推送代码与运行报告。
