# Spec 001：跨境物流异常结构化分流

## 状态

已批准，进入实现阶段。

## 背景与目标

当前 Agent 已能通过自然语言回答物流异常，但异常分类结果主要停留在模型回复中，前端和后续工单流程无法稳定复用。此功能把异常描述转换为固定结构，作为后续人工工单、运营统计和评测的稳定接口。

## 范围

### 必须实现

1. 提供 `POST /api/logistics/exception-classify` 接口。
2. 输入只包含 `description`，长度限制为 1-2000 字符。
3. 返回 `category`、`severity`、`required_materials` 三个字段。
4. 分类结果必须来自有限类别：清关补料、包裹破损或少件、疑似丢失、收件信息问题、派送异常、运输延误、其他异常。
5. 保持纯规则、可重复、无需调用外部模型；异常输入返回明确的 4xx。
6. 复用内置 `classify_logistics_exception` 工具，接口不得复制另一套分类规则。

### 不在本次范围

- 自动提交工单或修改真实运单。
- 引入新的数据库表。
- 模型微调和训练数据重构。

## 接口契约

请求：

```json
{"description":"包裹在清关，海关要求补资料"}
```

响应：

```json
{"category":"清关补料","severity":"medium","required_materials":"运单号、收件人信息、承运商通知截图"}
```

## 验收标准

- 正常清关、破损、丢失、地址和延误样例各返回对应分类。
- 空字符串、超长字符串返回 422。
- 接口测试和工具测试通过。
- README、API 文档和变更记录同步。
