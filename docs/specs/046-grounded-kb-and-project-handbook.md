# Spec 046：高频知识补库与项目深挖手册

## 背景

v5 在线 Agent 评测 300 条中政策流程通过 58/100。失分集中在收件信息修改、派送失败、商业发票等高频问题。当前仓库虽有相关片段，但缺少可直接回答操作步骤的成体系材料。用户还需要一份离线可打开、与当前代码一致的深度项目讲解及面试复习手册。

## 范围

1. 从 v5 失败样本定位 3–5 个高频知识缺口。只补有现有代码/材料或官方承运商文档支撑的内容；明确“本项目演示流程”与外部承运商规则的边界，不写未核实的时效、费用或法律承诺。语料文件提交 Git，但不含 API 密钥或真实用户数据。
2. 沿现有 `documents.build_chunks → knowledge_chunks(pending) → 向量化 → Milvus` 路径做增量录入，不重建/清空现有知识库。验证切块、查重、向量数量和针对性检索。向量化调用外部服务仅发送本轮新增公开语料。
3. 生成一个独立、离线可打开的 HTML 手册，覆盖项目定位、功能边界、技术栈与目录、前后端/Agent/MCP/RAG/数据库/观测/评测/分类器的数据流、关键状态与降级、安全边界、部署和故障排查、v3/v5 评测解释、可复现演示脚本。关键流程使用可缩放 SVG/HTML 图、交互式目录或步骤展开；不得把运行产物或密钥嵌入 HTML。
4. 面试题部分包含传统基础、Agent/RAG、工程与评测、项目追问四层，每题给出回答提纲、对应本项目代码锚点、常见误区；区分“已实现”“局限”“合理扩展”，不夸大主链路分类器或实时第三方数据。
5. 加验证：语料切块/来源清单测试、HTML 静态完整性/脚本检查、全量 pytest、知识检索和少量在线回答回归。对比同一高频题前后结果，不要求再次对 300 条全部调用模型。完成后安全审计并按项目约定提交推送；阿里云服务器暂不部署。
6. 若回归发现补库后仍被意图路由绕开知识证据闸，仅对明确的“登录后能查看哪些运单”类能力说明问法做窄范围确定性路由修正；具体单号查询继续走工具。加入边界测试。

## 验收

- 新增语料有明确来源、适用范围和不确定性提示；MySQL 中成功落 pending/done，Milvus 与 MySQL 状态一致。
- 至少 3 个此前失分的高频问法能召回相应新块，在线回答有依据或合理拒答，不虚构具体规则。
- HTML 双击或本地服务打开可阅读，目录、图表和题目展开可用，移动宽度无严重溢出；准确标注当前版本和评测口径。
- 全量测试通过；密钥、原始评测回答、数据库/索引运行产物不进入 Git。

## 实现记录

- 新增 `data/kb/service-playbook.md`，覆盖派送失败、地址修改、商业发票、演示账户权限和承运商选择五类高频问题；外部通用规则只采用 UPS/DHL 官方公开页面，并在语料中标注适用边界。
- 注册第 7 个知识源；本地预览得到 6 个新块、重复 0。增量录入和向量化成功 6 块，本地状态为 MySQL `done=25/pending=0`、Milvus 25；没有清空或重建已有知识库。
- 四组原 0/5 高频题增量回归：派送问题 5/5、地址修改 5/5、贸易单证 5/5、账户权限 3/5，合计 18/20。账户权限先因“运单”一词误走业务路，增加了只覆盖“登录后能查看哪些运单/权限范围”的窄路由规则；具体单号查询仍走工具。余下两题由语义证据自检保守拒答，保留为真实限制。

- 验证：HTML 内联 JavaScript 通过 `node --check`；新增手册/路由/知识源定向测试 29 项通过；完整测试 `591 passed`。变更文件密钥模式扫描无命中，`git diff --check` 通过。
- 浏览器自动化不允许直接打开本地 `file://` 页面，因此没有绕过安全策略；以 HTML 解析测试、锚点完整性、内联脚本语法、离线依赖检查和响应式 CSS 做自动验收。文件可由用户双击或用任意本地静态服务打开。
