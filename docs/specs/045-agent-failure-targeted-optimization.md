# Spec 045：Agent 评测失分定向优化

## 背景

v3 在线基线 300/300、请求失败 0、规则通过 163/300。主要失分为工具题 36 条未命中预期工具、政策题 45 条证据不足、跨文档 10 条未澄清缺失运单号、库外题 19 条未通过严格拒答规则。原始报告仅留本机，不提交模型回答。

## 范围与边界

1. 先改真实产品行为：缺运单号时明确追问，而不是给笼统的证据不足话术；对明确的寄运物品预检，让 `check_prohibited_item` 在合适路线上可被调用，输出仍须注明承运商和目的国最终审核，不将本地关键词预检当作海关法规。
2. 对明显超出知识库或缺少实时/内部数据的请求，给出明确无法确认与下一步，不伪造事实。检索后拒答是允许的安全路径；评测记录要把严格工具零调用口径与安全拒答口径区分，不用修改评分掩盖产品失分。
3. 政策/跨文档证据不足不得为了提高通过率而放松证据闸；仅在检索命中和语义核验均支持时才作答。高频真缺知识单独记录，待有可靠语料再补。
4. 抽查 v4 跨文档通过样本时发现模型在用户未给重量的情况下擅自按 1kg 调用报价工具。新增执行侧参数来源守卫：缺重量不能执行 `estimate_shipping_fee`，须先追问；保留其他已给足参数的报价路径。v4 的 140 条仅作诊断，不作为最终成绩；修复后用 v5 独立报告从零跑 300 条。
5. 以 v3 基线为对照，运行单测、少量人工可读端到端样本及同 300 条 v5 在线评测。新报告使用独立 Git 忽略路径；给出总量和五类分类差异、请求错误、代表性回归风险。

## 验收

- 无运单号查询/SLA 能明确索取运单号；有号仍正常调用工具。
- 禁限寄预检不把“需审核”写成“可寄”，危险品不被误判为可寄。
- 库外/实时内部资料不能编造；明确拒答或说明缺少可验证资料。
- 无重量时不能出现具体运费报价；用户补充重量后可调用估价工具。
- 全量 pytest 通过；v5 300 条完成且报告可与 v3 对照。若无法全跑，明确已完成和原因。
- `.env`、原始 v3/v4/v5 回答和运行报告不进 Git；部署服务器不在本轮范围。

## 实现记录

- 物品寄运预检的显式问法从知识路转至 Agent 工具路；一般禁限寄政策仍先过知识证据闸。提示词明确 `check_prohibited_item` 只是本地预检，不能外推为所有承运商或海关法规。
- 知识证据弱时，涉及实际运单节点、改址、退运的问法如未提供运单号，明确索取运单号，同时不承诺费用承担；笼统的“其他”话术改为明确无法确认并索取关键信息。
- 报价工具新增执行前守卫：用户最近两轮原话必须包含与调用参数一致的重量；本轮有新重量时不得沿用上一票的旧重量。缺重量的跨文档题只说明禁限寄风险和所缺报价参数，不给凭空的 1kg 金额。有重量的 0.8kg 特快题仍正常估价。申报价值未知时只给运费，说明税费无法可靠估算。
- 首轮 v4 在 140/300 时人工抽查发现未给重量却按 1kg 估价，故保留该本地诊断报告但不作为最终成绩。修复后 v5 完整执行 300 条；两条读取超时以 `--resume --retry-failed` 串行补跑，最终请求失败 0。
- 同 300 题严格行为规则对比：v3 163/300（54.33%）→ v5 210/300（70.00%）。政策流程 55→58/100，跨文档 43→57/70，工具操作 24→38/60，库外拒答 31→43/50，边界澄清 10→14/20。分数只代表当前规则命中，不能当作事实准确率或因果证明；模型输出波动仍存在。
- v5 规则通过的 38 条工具题均有至少一项成功工具结果。库外拒答剩余 7 条均为先调用 `query_faq` 再明确拒答，因严格规则要求零工具调用而记失败；政策流程仍有 42 条、跨文档仍有 13 条缺足够证据，不能靠降低证据闸放行。工具题另有 22 条无预期调用，多数涉及建工单必填资料或运单号不足，应按业务安全性逐例处理。
- v3/v4/v5 原始报告均匹配 `.gitignore`，仅本机保留，不提交或上传；阿里云服务器未部署本轮变更。
- 最终全量 pytest **588 passed**。重启本地服务后的两轮烟测：上一票 1.5kg、下一票 0.8kg，报价工具接收 0.8kg，未沿用旧重量；Agent 评测页读取 v5 为 `ok`、300/300。
